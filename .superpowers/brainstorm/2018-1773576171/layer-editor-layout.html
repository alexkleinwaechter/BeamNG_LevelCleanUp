DecalRoad Layer Set Editor — Component Layout

This reusable component will be used in 3 contexts: Defaults editor, Per-material override, and (future) Per-OSM-feature override. Which layout feels right?

A

List + Detail Panel (BeamNG-style)

Layer list on top with selectable rows (name, material chip, enable toggle). Selected layer expands a detail panel below with sliders for width, position, fade, priority. Matches BeamNG's roadSpline editor pattern.

Pros

  • Familiar to BeamNG users
  • Compact — fits in expansion panel
  • Good for many layers

Cons

  • Two-level interaction (select then edit)
  • Can't see all properties at once
B

Inline Cards (Accordion)

Each layer is an expansion panel card showing key info in the header (name, material, type chip, enable toggle). Expand to see all properties inline. No separate detail panel.

  • All info visible in headers
  • Drag-to-reorder natural with cards
  • Matches existing MudBlazor expansion pattern in app

Cons

  • Takes more vertical space when expanded
  • Only one layer editable at a time (accordion)
C

Compact Table with Inline Edit

Data grid / table with editable cells. Each row = one layer. Columns for key properties (type, material, width, position, flags). Click to edit inline. Add/remove via row actions.
